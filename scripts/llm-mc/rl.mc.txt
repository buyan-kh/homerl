=== llm-rl-01
W An MDP is (S, A, P, R, gamma, rho_0): states, actions, transition kernel, reward, discount, and start distribution. The objective is the expected discounted return of trajectories sampled from the policy, not a supervised next-token loss.
+ (S, A, P, R, gamma, rho_0). Maximize the expected discounted return of trajectories sampled from the policy.
- (X, y, loss) only. The objective is to minimize cross-entropy on a fixed dataset, with no transitions.
- An MDP has no discount or start distribution, and the objective is to maximize the reward of the first step only.
- The policy is part of the MDP tuple, and the objective is to match a human demonstration token for token.

=== llm-rl-02
W The return is G_t = r_t + gamma G_{t+1}. gamma < 1 makes the infinite sum well defined and weights near-term reward more; the effective horizon is about 1/(1-gamma). LLM RL with a terminal reward is often run at gamma = 1, because there is no infinite continuing stream.
+ G_t = r_t + gamma G_{t+1}. The horizon is about 1/(1-gamma). LLM RL with a terminal reward often uses gamma = 1.
- The return is the last reward only, and gamma is the learning rate. LLM RL always uses gamma = 0.
- Discounting is required even for a one-step bandit, and gamma = 1 is undefined for any finite episode.
- G_t = gamma^{t} r_0, so later rewards are up-weighted, and the horizon is gamma itself.

=== llm-rl-03
W Token-level: state is the prompt plus tokens so far, action is the next token, transitions are deterministic, and the reward is often sparse at the end. Sequence-level: the whole completion is one bandit action with one reward. Both are used; the first is the usual MDP view, the second is why methods like RLOO feel like a contextual bandit.
+ Token-level: state is prompt plus tokens so far, action is the next token, deterministic transitions, sparse terminal reward. Sequence-level: one bandit action for the whole completion.
- Token-level uses a random environment transition after every token, and sequence-level has no reward at all.
- The two views are identical to a supervised language-modeling MDP with a reward at every character.
- LLM generation cannot be an MDP because the state is text, so only bandits with no state are valid.

=== llm-rl-04
W LLM RL is episodic: a rollout ends at EOS or a cap. The horizon can be thousands of tokens, so credit assignment is hard and variance is high. If you truncate, you must treat the bootstrap or the terminal flag honestly, or you will teach the model the wrong thing about long answers.
+ LLM RL is episodic with very long horizons, so credit assignment and variance are hard. Handle truncation explicitly.
- LLM RL is a continuing task with no episodes, so truncation cannot happen and horizons stay short.
- Horizon is only the number of prompts in the batch, not the tokens in a response, so credit assignment is trivial.
- Episodic tasks cannot use a terminal reward, which is why LLM RL must be continuing.

=== llm-rl-05
W V(s) is the expected return from a state under the policy. Q(s,a) is the expected return after taking a, then following the policy. A(s,a) = Q - V, and under the policy it has mean zero: good actions are above average, bad ones below.
+ V is the expected return from s, Q is the expected return after taking a, and A = Q - V, which has mean zero under the policy.
- V is the max over actions, Q is a probability, and A is always positive, which is why you clip it.
- A = V - Q, so taking the greedy action always has negative advantage.
- V, Q, and A are three names for the immediate reward, and they differ only at terminal states.

=== llm-rl-06
G bellman
W Start from G_t = r_t + gamma G_{t+1}, take expectations, and use the Markov property so the future return depends on s' only. That is V_pi(s) = E[r + gamma V_pi(s') | s, a ~ pi]. It is an expectation under the current policy, not a max.
+ V(s) = E[r + gamma V(s')], from G_t = r_t + gamma G_{t+1} and the Markov property. It is an expectation under pi, not a max.
- V(s) = max_a [r + gamma V(s')], which is the expectation equation, and the dynamics can be ignored.
- The Bellman expectation equation is V(s) = r, because future value is already in the reward by definition.
- You cannot derive V from the return identity, because G_t is only defined for continuing tasks.

=== llm-rl-07
W Optimality is V*(s) = max_a E[r + gamma V*(s')]. Value iteration applies that backup with a model. Q-learning applies a sampled max backup without a model. These are rarely the main tools for LLM policy training, where we use policy gradients, but the equation is still the definition of an optimal value.
+ V*(s) = max_a E[r + gamma V*(s')]. Value iteration uses a model; Q-learning uses samples. They are rarely the main LLM training method.
- The optimality equation is the same as the expectation equation, with no max, and Q-learning requires a full model.
- Value iteration is the PPO loss, and Q-learning is how GRPO computes advantages.
- There is no optimality equation for discrete actions, so these methods do not apply to tokens.

=== llm-rl-08
W The TD error is delta_t = r_t + gamma V(s_{t+1}) - V(s_t). Monte Carlo uses the full return: unbiased, high variance. TD uses a bootstrap target: lower variance, biased if V is wrong. If V is exact, E[delta | s,a] is the advantage.
+ delta_t = r_t + gamma V(s_{t+1}) - V(s_t). MC is unbiased and noisy; TD is lower variance and biased. E[delta] = A when V is exact.
- TD is unbiased and Monte Carlo is biased. The TD error is V(s) - r, with no next-state term.
- Monte Carlo and TD are identical once you use a discount, and delta is the policy entropy.
- E[delta] is always 0, even if V is wrong, so it cannot estimate an advantage.

=== llm-rl-09
G policy-gradient
W Because grad p = p grad log p, we have grad E_p[f] = E_p[f grad log p]. f can be a black-box reward; you do not need to differentiate the environment. Also E[grad log p] = 0, which is why baselines work. This is the score-function identity.
+ grad E[f] = E[f grad log p], because grad p = p grad log p. f can be a black box, and E[grad log p] = 0.
- grad E[f] = E[grad f], so you always need to differentiate the reward and the dynamics.
- The score function is grad p without the log, and E[grad log p] is 1, not 0.
- The trick only works if f is a linear function of the action, not for a black-box reward.

=== llm-rl-10
W The log density of a trajectory splits into policy terms plus environment terms. Only grad log pi(a_t | s_t) depends on the parameters, so the dynamics drop out. The policy gradient is E[R(tau) sum_t grad log pi(a_t|s_t)].
+ grad log p(tau) = sum_t grad log pi(a_t|s_t), because dynamics do not depend on theta. So grad J = E[R(tau) sum_t grad log pi].
- The dynamics stay in the gradient, so you need a model of P(s'|s,a) to do policy gradient.
- grad J = E[grad R(tau)], with no log pi term, which is why dynamics drop out.
- Only the last action's log-prob appears; earlier tokens have no gradient because the reward is terminal.

=== llm-rl-11
W Rewards that happened before time t do not depend on a_t, and E[grad log pi(a_t|s_t) | past] = 0, so those past rewards vanish in expectation. You can use the reward-to-go G_t, or Q, instead of the full episode return R(tau). That is causality, and it already cuts variance.
+ Past rewards multiply a zero-mean score, so they vanish in expectation. Use the reward-to-go G_t (or Q), not the full R(tau).
- You must use the full R(tau) at every t, because dropping past rewards biases the gradient.
- Causality means future rewards also vanish, so only the immediate r_t should be used, never G_t.
- Reward-to-go is only valid when gamma is 0, otherwise you have to use R(tau).

=== llm-rl-12
W For a baseline that does not depend on the action, E_a[grad log pi(a|s)] b(s) = b(s) grad sum_a pi(a|s) = b(s) grad 1 = 0. So subtracting b(s) does not change the expected gradient. V(s) is the usual choice because it also cuts variance.
+ E_a[grad log pi(a|s)] b(s) = 0, so any action-independent baseline is unbiased. V(s) is the natural one.
- Only a constant baseline is unbiased. A state-dependent V(s) would bias the gradient.
- You must subtract Q(s,a), an action-dependent baseline, or the gradient is biased.
- Baselines change the expected gradient, which is how they reduce variance.

=== llm-rl-13
W Softmax of [1,0,0] is about [0.576, 0.212, 0.212]. The score is onehot(a) - pi, so for arm 0 it is about [0.424, -0.212, -0.212]. A step z <- z + lr * reward * score with lr=0.5 and reward 1 gives about [1.212, -0.106, -0.106]. The other arms are pushed down.
+ grad_z log pi(arm 0) = onehot - pi ≈ [0.424, -0.212, -0.212]. With step size 0.5 and reward 1, z becomes about [1.212, -0.106, -0.106].
- The gradient is [1, 0, 0], and z becomes [2, 0, 0], because softmax backwards is the identity.
- pi is [1,0,0] already, so the score is zero and z does not change.
- The score is pi - onehot, so arm 0 is pushed down and the other arms go up after a positive reward.

=== llm-rl-14
CODE
W Sample a completion, score it, subtract a baseline to get A, then the loss is -A times the sum (or mean) of token log-probs on the response, take one optimizer step, and sample again. Do not backprop through the reward. Mask the prompt tokens.
+ Sample a response, score it, subtract a baseline, and use loss = -A * (sum of response token log-probs). Then step and resample. Do not differentiate the reward.
- loss = A * sum of all prompt and response log-probs, and backprop through the grader as well.
- REINFORCE for LLMs is ordinary SFT on the rejected samples, with no baseline and no sampling.
- You should step the optimizer once per token with A equal to the raw logit, then never resample.

=== llm-rl-15
W Variance comes from long random trajectories and a noisy reward. Standard tools are reward-to-go, baselines, a learned critic or GAE, discounting, advantage normalization, more samples or larger groups, and trust-region or clipped updates so one noisy batch cannot jump too far.
+ Use reward-to-go, baselines, critics or GAE, discounting, advantage normalization, more samples, and trust regions or clipping.
- The only tool is to raise the learning rate, which reduces variance by shrinking the policy faster.
- Variance is not a problem for policy gradient, so you should not subtract a baseline or normalize advantages.
- Trust regions increase variance, which is why PPO removes the clip in production LLM runs.

=== llm-rl-16
G grpo-group
W RLOO sets A_i = R_i minus the mean of the other k-1 rewards in the group, which is an unbiased, critic-free leave-one-out baseline. Ahmadian et al. argued that with a strong SFT start, RLHF is close to a bandit, so a simple REINFORCE-style estimator can be enough, without a PPO critic stack.
+ A_i = R_i minus the mean of the other k-1 rewards: unbiased and critic-free. A strong SFT start makes RLHF more bandit-like, so REINFORCE-style methods can be enough.
- RLOO trains a large critic, and the paper argues REINFORCE is never enough for RLHF.
- RLOO uses A_i = R_i without a baseline, which is biased, and that is why it needs PPO.
- Leave-one-out is only for eval, not for advantages, and it requires a value network.

=== llm-rl-17
W For [1,0,0,1,1] the mean is 0.6. RLOO uses the mean of the other four: a 1 gets 1-0.5=+0.5, a 0 gets 0-0.75=-0.75. GRPO uses (r-mean)/population std, and the population std is about 0.49, so the z-scores are about +0.816 and -1.225. Do not mix the two baselines.
+ Mean is 0.6. RLOO is +0.5 for a 1 and -0.75 for a 0. GRPO with population std about 0.49 is about +0.816 and -1.225.
- Both methods give +0.4 and -0.6, the raw deviations from 0.6, with no leave-one-out and no std.
- RLOO is +1 and 0, and GRPO is +1 and -1 after a min-max scale, independent of the group mean.
- The group is too small for a baseline, so both advantages are just the raw rewards [1,0,0,1,1].

=== llm-rl-18
G gae-lambda
W n-step advantages can be mixed with weights that form a geometric series in (gamma lambda). That sum is GAE: A_t = sum_l (gamma lambda)^l delta_{t+l}, and it is computed backwards as A_t = delta_t + gamma lambda A_{t+1}. You do not need a separate n for each term if you use that recursion.
+ A_t = sum_l (gamma lambda)^l delta_{t+l}, computed backwards as A_t = delta_t + gamma lambda A_{t+1}.
- GAE is A_t = delta_t only, with no recursion, and n-step estimates cannot be mixed.
- A_t = sum_l lambda^l r_{t+l}, with no TD errors and no gamma in the mix.
- The backward recursion is A_t = A_{t+1} - delta_t, which is how you subtract the future.

=== llm-rl-19
W lambda=0 is one-step TD: A_t = delta_t, lower variance, more bias if V is wrong. lambda=1 is the Monte Carlo advantage (return minus V), unbiased if you have a true return, but noisy. You pick something in between, often around 0.95, to trade the two.
+ lambda=0 is one-step TD (lower variance, biased). lambda=1 is Monte Carlo minus the baseline (unbiased, noisy). Pick a value in between.
- lambda=0 is Monte Carlo, and lambda=1 is one-step TD, the reverse of the definitions.
- Both endpoints are unbiased and have the same variance, so lambda is only a learning-rate scale.
- You should always use lambda=0 for LLMs, because Monte Carlo is undefined when gamma is 1.

=== llm-rl-20
W With gamma=1, deltas are 0+0.6-0.5=0.1, 0+0.8-0.6=0.2, and 1+0-0.8=0.2. Then A_2=0.2, A_1=0.2+0.95*0.2=0.39, A_0=0.1+0.95*0.39=0.4705. The MC advantages would be [0.5, 0.4, 0.2]. GAE sits between TD and MC.
+ Deltas are [0.1, 0.2, 0.2], GAE is [0.4705, 0.39, 0.2], and MC would be [0.5, 0.4, 0.2].
- Deltas are [0, 0, 1], and GAE equals the rewards, [0, 0, 1], because gamma is 1.
- GAE is [0.1, 0.2, 0.2], equal to the deltas, because lambda=0.95 is treated as 0.
- MC and GAE are both [1, 1, 1], because the return is 1 at every step when gamma is 1.

=== llm-po-10
W An advantage says whether an action was better than average from that state. GAE is a specific estimator that blends TD errors with a lambda tradeoff between bias and variance, rather than using a single one-step or Monte Carlo target.
+ Advantage means better than average. GAE blends TD errors to trade bias for variance.
- Advantage is the raw reward, and GAE is a second optimizer used instead of AdamW.
- GAE removes the need for a value function, and the advantage is always the last reward only.
- Better than average is a Q value, not an advantage, and GAE is a trust-region constraint.

=== llm-rl-21
CODE
W For right-padded sequences, walk backward over T, use a not-done (or not-pad) mask so you do not bootstrap through padding or the end, and set A_t = delta_t + gamma * lam * notdone * A_{t+1} with delta = r + gamma V_next * notdone - V. Then maybe normalize over the valid tokens.
+ Walk backward over T: delta = r + gamma V_next * notdone - V, and A = delta + gamma lam * notdone * A_next, with padding masked out.
- Walk forward and set A = r at every pad token, with no notdone mask, which is how you handle right padding.
- GAE in PyTorch is a single vmap over the batch with V_next = V always, even after terminal.
- You should compute A only at the last token and broadcast it, ignoring the backward recursion.

=== llm-rl-22
G actor-critic
W The actor is the policy, the critic is a value model used to form advantages. The usual loss is a policy term -A log pi (or a clipped surrogate), a value term c_v (V - target)^2, and often an entropy bonus -c_e H. The two heads can share a trunk or be separate models.
+ Actor is the policy, critic is V used for advantages. Loss is typically -A log pi + c_v (V - target)^2 minus an entropy bonus.
- Actor-critic means two copies of the policy and no value loss. Entropy terms are illegal in this method.
- The only loss is the value loss. The actor is updated by copying the critic weights.
- Actor-critic is a supervised method where the critic labels tokens, and A is not used.

=== llm-rl-23
W In LLM PPO the value is usually a scalar head on a separate model, often initialized from the reward model, producing a per-token (or last-token) value. A critic on the same weights as the policy is also possible but messy. Critics are hard in this setting because the reward is sparse and the scale moves, so people sometimes drop them (GRPO, RLOO).
+ Usually a per-token scalar head, often a separate model initialized from the RM. Critics are hard here, which is why some methods drop them.
- The value is always the same model as the policy, with no design choices, and it is trained by SFT on the reward.
- LLM PPO cannot use a value head, so advantages must be raw rewards, and initializing from the RM is harmful.
- The critic is a classifier of prompts, not a return estimator, and it should not be initialized from the RM.

=== llm-rl-24
W Value clipping, like PPO's policy clip, clips V_new to a band around V_old and takes a conservative value loss (often the max of clipped and unclipped errors). Several studies found little consistent benefit, and it can depend on reward scale, so it is a knob to ablate, not a must.
+ Clip V_new to a band around V_old and take a conservative loss. Studies often found little benefit, so ablate it.
- Value clipping is required for PPO to work, and it should always use the same eps as the policy clip with no ablation.
- Value clipping replaces the value loss entirely, and it is the main reason PPO beats REINFORCE.
- You clip the reward to V_old, not the value head, which is what the original PPO paper does.

=== llm-rl-25
W A large policy step can make the next batch of samples terrible, and you may not recover ("poisoned data"). Also, a small parameter change can be a large change in the distribution (KL). Trust regions or clips bound how far the new policy may move, usually in KL, so updates stay conservative.
+ A bad step can poison the next data, and parameter distance is not policy distance. Bound the KL (or clip the ratio) per update.
- Large steps are always better, and parameter L2 distance already is the KL, so no trust region is needed.
- Trust regions are only for supervised learning, and policy gradient is already safe at any LR.
- The problem with large steps is only GPU overflow, not data quality or distribution shift.

=== llm-rl-26
W The performance difference can be written with states from the old policy and an importance weight pi/pi_old on the actions, giving the surrogate L = E_old[(pi/pi_old) A]. At pi = pi_old the gradient of L is the usual policy gradient. That is the TRPO/PPO starting point.
+ L = E_old[(pi/pi_old) A], which matches the policy gradient at pi = pi_old, using states from the old policy and IS on actions.
- The surrogate is E_new[A] with no importance weight, which is why TRPO does not need an old policy.
- L = E[log pi], with no advantage, and it is not equal to the policy gradient at the old policy.
- Importance sampling is only used at eval time, never in the TRPO or PPO training objective.

=== llm-rl-27
W TRPO maximizes that surrogate subject to a hard mean-KL constraint to the old policy. It uses a natural gradient, often with conjugate gradient and Fisher-vector products, then a line search to stay inside the constraint. PPO later replaced that machinery with clipping.
+ Maximize the surrogate subject to mean KL <= delta, with a natural gradient (conjugate gradient and Fisher-vector products) and a line search.
- TRPO minimizes the KL with no surrogate, solved by plain SGD, which is why it is cheaper than PPO.
- The constraint is on parameter L2, not KL, and the solver is a closed-form softmax.
- TRPO is just PPO with a smaller clip, and it does not use a Fisher or a line search.

=== llm-rl-28
W The natural gradient is the steepest ascent direction when you measure step size in KL, not in Euclidean parameter space. It is F^{-1} g, where F is the Fisher information of the policy. That makes the update invariant to how you parameterize the policy (up to the usual technical conditions).
+ It is steepest ascent under a KL metric: a step proportional to F^{-1} g, with F the Fisher. That is invariant to reparameterization.
- The natural gradient is just g / ||g||, and it depends strongly on how you parameterize the policy.
- Invariance means the Fisher is the identity, so the natural gradient equals the vanilla gradient always.
- Natural gradients are only defined for linear policies, not for softmax over tokens.

=== llm-po-08
G ppo-clip
W The PPO clipped objective is the minimum of r A and clip(r, 1-eps, 1+eps) A, with r = pi/pi_old and eps often 0.2. Clipping stops a single update from changing the probability ratio too much in the direction that would further increase the objective.
+ The objective is the importance ratio times the advantage, clipped to a band around 1, often 1 +/- 0.2, which limits how far one update can move the policy.
- PPO clips the reward to +/- 0.2 and does not use an importance ratio, which is how it prevents large steps.
- The clip is applied to the logits, not the ratio, and eps=0.2 means a 20% dropout on actions.
- Clipping forces the ratio to 1 always, so the policy cannot change, which is a common misunderstanding of the min.

=== llm-rl-29
W With eps=0.2, clipping blocks the gradient only when the ratio is already outside [0.8, 1.2] in the direction that would raise the objective: r=1.5 with A=2 is clipped, r=0.7 with A=2 is not, r=0.7 with A=-1 is clipped, and r=1.5 with A=-1 is not. Inside the band, or when the ratio is "too close" in the bad direction, the unclipped term can still flow.
+ Clip blocks the gradient only when the ratio is already outside [0.8, 1.2] in the helpful direction: (A=2, r=1.5) and (A=-1, r=0.7) are clipped; the other two still have a gradient.
- All four cases are clipped, because 1.5 and 0.7 are both not equal to 1, so no case has a gradient.
- None of the four cases are clipped, because eps=0.2 only applies to the value head.
- (A=2, r=0.7) is the only clipped case, because ratios below 1 are always clipped, regardless of A.

=== llm-rl-30
W A full iteration: collect rollouts, compute GAE, often normalize advantages, then K epochs of minibatches with clipped policy loss, a value loss, and an entropy bonus, plus grad clipping and a small LR. Then refresh rollouts. The hyperparameters (K, clip, epochs, minibatch) matter as much as the formula.
+ Rollouts, GAE, often normalize A, then K epochs of minibatches with clipped policy loss, value loss, and entropy, plus grad clipping. Then resample.
- One big batch of SFT on the best rollout, with no GAE, no clip, and no epochs, which is the full PPO iteration.
- PPO has no minibatch epochs; you must use each rollout once, and there is no value or entropy term in the official method.
- The iteration is just AdamW on the reward model, then a frozen policy, with no rollouts.

=== llm-rl-31
W Log approximate KL to the old policy, clip fraction, entropy, value explained variance, reward mean and spread, KL to the reference, response length, and grad norm. Together they tell you if you are stepping too hard, collapsing, hacking length, or training a dead critic.
+ Log approx KL, clip fraction, entropy, value explained variance, reward stats, KL to the reference, length, and grad norm.
- The only useful log is the training reward. The rest is noise and should be hidden so you do not overreact.
- Clip fraction should always be 1, and entropy should go to 0 as fast as possible, which is success.
- Grad norm and length are not PPO diagnostics, and KL to the reference should not be logged in RLHF.

=== llm-rl-32
W A lot of PPO's reported edge came from code-level details: advantage normalization, Adam eps, reward scaling, when to clip, how to init, LR annealing, and eval settings. If you compare methods, you have to control those, or you are comparing implementations, not ideas.
+ Code-level choices like normalization, init, LR annealing, and clipping details drove much of PPO's edge. Control them in comparisons.
- Implementation details do not matter for PPO, which is why every repo gets the same numbers from the formula alone.
- The only detail that matters is the clip eps, and everything else can be left at PyTorch defaults.
- Papers that change logging or init are not changing PPO, so you can ignore those when you reimplement.

=== llm-fd-14
W Forward KL(p||q) is mode-covering: q must put mass on all modes of p, which is the usual pretraining or teacher-forcing direction (p is data). Reverse KL(q||p) is mode-seeking: q can drop modes and concentrate, which shows up in some RL and distillation objectives. Mixing them up explains a lot of "why is my model peaked" confusion.
+ Forward KL is mode-covering (pretraining). Reverse KL is mode-seeking (it can drop modes). Both show up in LLM training.
- Forward KL is mode-seeking, and reverse KL is mode-covering, the reverse of the usual picture.
- The two KLs are equal for softmax models, so the mode-covering vs mode-seeking distinction never appears.
- Pretraining uses reverse KL, which is why language models are mode-seeking from step 0.

=== llm-po-07
W The KL term keeps the policy near the SFT (or other) reference so it does not hack the reward by leaving the distribution of reasonable text. The per-token reward often looks like r_final at the last token, minus beta times a per-token log-ratio KL, which then flows into GAE or a similar estimator.
+ Subtract a beta * KL-to-reference term from the reward (or the loss). That KL is the leash against reward hacking.
- The KL penalty is added to encourage leaving the reference, which is how RLHF explores, and there is no per-token form.
- KL is only computed at eval, not in the training reward, so it cannot act as a leash.
- The reference is the reward model, not the SFT policy, and beta should be 0 for all LLM runs.

=== llm-rl-33
W A KL constraint (or clip) to pi_old is a trust region for update stability. A KL penalty to a fixed pi_ref is part of the objective, to stay near a good SFT model. An adaptive controller raises or lowers beta to keep the realized KL near a target. Do not mix the two KLs up in a log plot.
+ KL to pi_old is a trust region for stability. KL to pi_ref is an objective regularizer. An adaptive controller moves beta to hit a KL target.
- The two KLs are the same term, and an adaptive controller is only used to change the learning rate, not beta.
- A constraint to pi_ref and a penalty to pi_old is the standard split, the reverse of the usual roles.
- Adaptive KL controllers set gamma, not beta, and they are unused in RLHF.

=== llm-rl-34
W k1 is log(q/p), unbiased but can be negative and noisy. k2 is (log r)^2 / 2, a squared approximation. k3 is (r-1)-log r, which is unbiased for the KL and nonnegative, a nicer training term. GRPO uses a k3-style estimator in the loss. Know which one you are logging.
+ k1 = log(q/p) is unbiased and noisy; k2 is (log r)^2 / 2; k3 is (r-1)-log r, unbiased and nonnegative. GRPO uses k3 in the loss.
- GRPO uses k1 only, and k3 can be negative, which is why it is avoided.
- All three estimators are identical, and GRPO does not include a KL term at all.
- k2 is unbiased and used by GRPO, and k1 is the nonnegative one.

=== llm-rl-35
W A KL in the reward is folded into the return and then into advantages, so its gradient path is through A. A KL in the loss is an explicit extra term on the log-ratio (or k3) with its own coefficient. They are not the same gradient, and recipes pick one or both carefully, especially in RLVR-style papers.
+ In the reward, -beta log-ratio flows through advantages. In the loss, you add an explicit KL estimator. The gradients differ, and recipes choose deliberately.
- The two placements give identical gradients always, so you can swap them with no change in the run.
- KL in the reward is illegal, and KL in the loss cannot be used with advantages.
- RLVR recipes never discuss this choice, because they use no KL term of either kind.

=== llm-rl-36
W Bradley-Terry says P(w > l) = sigmoid(r_w - r_l). The MLE is L = -log sigmoid(r_w - r_l). Only differences of rewards matter, so an additive constant on r is free, and people often normalize or constrain the scale. That is the pairwise RM loss.
+ P(w>l)=sigmoid(r_w-r_l), so MLE is L=-log sigmoid(r_w-r_l). Only differences matter, and the scale should be normalized or constrained.

- The right fix is to ignore the mismatch, because a clip in PPO already implements TIS.

=== llm-rl-59
W V-trace (IMPALA) is for actor-learner setups: actors generate, a learner updates, and value targets use truncated importance-sampling products (rho-bar, c-bar) so stale trajectories do not explode. The same idea, truncated IS on slightly stale rollouts, is why it shows up in async LLM RL systems.
+ It is an actor-learner method whose value targets use truncated IS products, which keeps stale async trajectories from exploding. That is why it matters for async LLM RL.
- V-trace is a on-policy GAE with no IS, and it is unrelated to actor-learner or async LLM systems.
- IMPALA requires a single GPU and no truncation, which is why V-trace is unused in async stacks.
- rho-bar and c-bar are entropy bonuses, not truncated IS coefficients.

=== llm-rl-60
W A practical GRPO/RLVR loop is: sample prompts in a difficulty band, generate G completions each, grade them, filter useless groups, compute advantages, recompute train-time log-probs, apply clipped updates plus a KL or ref term, sync generation weights, and repeat. Treat generation, grading, and the trainer as a system, not a single loss line.
+ Sample band-filtered prompts, generate G each, grade, filter, compute advantages, recompute log-probs, apply clipped updates, and sync the generation weights.
- Train only on a static SFT set with no generation, no grader, and no weight sync, which is the RLVR loop.
- Generate once at the start of the run, reuse those samples forever, and skip filtering and log-prob recomputation.
- The loop is: update, then grade, then generate, so you never need to sync weights to the inference engine.

=== llm-ev-25
W Agent RL is usually rollout-bound: the env, tools, and long episodes cost more than the backward pass. Use warm process pools, async rollouts, retries, and careful isolation so env errors are not recorded as model errors. Optimize the waiting time, not just MFU of the trainer.
+ Agent RL is rollout-bound. Use warm pools and async rollouts, and separate environment errors from model errors.
- The backward pass dominates, so you should ignore rollout latency and only raise trainer MFU.
- Env errors should be treated as model failures in the reward, and async rollouts are unsafe.
- Warm pools are only for training-time data loaders, not for tool environments, and they do not help RL.

=== llm-rl-61
W Colocated systems share GPUs between generate and train, often resharding weights between phases. Disaggregated systems use separate GPU pools, overlap async rollouts with training, and broadcast or stream new weights, at the cost of staleness. The choice is about utilization and complexity, not a moral "true on-policy" rule.
+ Colocated: the same GPUs alternate generate and train, often resharding. Disaggregated: separate pools, async overlap, weight broadcast, and some staleness.
- Colocated always uses two clusters, and disaggregated means one GPU does everything with no staleness.
- There is no tradeoff: disaggregated is strictly better, with zero staleness and less complexity.
- Resharding and weight broadcast are not part of these designs, which only differ in the loss function.

=== llm-rl-62
